# BUILD-CLP-001-R Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close Q's three deferred durability gaps with append-only authoritative case-state history, database-native backup/restore verification, and correlation-bound certification reconstruction.

**Architecture:** Extend Q without changing frozen CLP-001 domain rules. PostgreSQL remains the production authority; state is recorded as append-only history per event rather than mutable projection. Backup/restore uses pg_dump/pg_restore verification, while replay reconstructs case-scoped certifications from persisted rows.

**Tech Stack:** TypeScript, Node.js 22, PostgreSQL 16, node:test, GitHub Actions.

**Spec:** Merged Q baseline `5427aff8c10370085546cf98ae83dacd5939bb0a` plus independent-review deferred findings.

## Global Constraints

- Parent repository baseline is exactly `5427aff8c10370085546cf98ae83dacd5939bb0a`.
- No resident or worker UI.
- No marketplace, payments, social/community, gamification, production identity federation, or expanded AI authority.
- Frozen CLP-001 transition/eligibility semantics are not modified.
- PostgreSQL remains the production persistence contract.
- Every authoritative state record is append-only and attributable to one event.

## Review Focus

- Null-decision event must preserve state rather than reset to `REPORTED`.
- State history must reject conflicting state for the same correlation/version.
- Backup restore must prove replay hash equivalence on a fresh PostgreSQL database.
- Certification reconstruction must be scoped to the requested correlation.
- Existing Q data must migrate without destructive rewrite.
